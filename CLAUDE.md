# bento-themes

Open source Bento slide-deck themes. Each theme is generated by `themes/<name>/theme.mjs` and spliced into the Bento runtime, never hand-written JSON.

## Before contributing

Activate the `bento-slides` skill. It carries the document format, element shapes and the authoring workflow; without it you will guess at keys the runtime drops silently. Anything in this file that contradicts the skill reflects behaviour verified against runtime 1.2.3 in this repo, and wins here.

## Workflow

1. `make build` writes `<Title>.doc.json` and `<Title>.bento.html` per theme.
2. `make check` renders each deck headlessly and writes `themes/<name>/preview/slide-NN.png`. It needs a Chromium-based browser and fails inside a sandbox that blocks the browser profile directory.
3. Read every PNG. Overflow, crowding and dropped keys are invisible in the JSON and obvious on screen. A contact sheet helps: `magick \( a.png b.png -resize 480x270 +append \) ... -append sheet.png`.
4. Fix every warning until `validate(): ok=true` with 0 warnings.

When adding a theme: run `make check`, commit the generated `preview/` PNGs, and add a README entry with two preview images that represent the theme.

## Conventions

- `scripts/lib.mjs` holds the element factories, `COLS` arithmetic and `assertDoc`. Use `factory(theme)` rather than writing element objects by hand.
- `assertDoc` is the guard rail: sharing off, no `fx`, `transition: "none"` everywhere, 14px type floor, unique ids, notes on every slide, placeholders for layout copy. Extend it rather than working around it.
- Every theme carries the same layout set with the same slide ids and element id prefixes, so a deck can swap themes without renaming elements. New layouts go into every theme.
- Templates are static by choice: no transitions, entrances, loops, step reveals or count-ups.
- Colour variants share one builder: `themes/mono-dark/theme.mjs` exports `makeMono(palette, opts)` and `themes/mono-light/theme.mjs` is 20 lines. Layout ids carry the variant slug.
- Craft floor: one accent colour, one or two typefaces, 96px side margins, body 22px sans or 26px serif, text contrast 4.5:1 and large text 3:1 (compute the ratios, do not eyeball them), content filling the band rather than pooling slack at the bottom.

## Gotchas

These cost a build-render cycle each to find. The full list is in the README under Gotchas; the ones that bite hardest:

**Write every typographic field on every element.** When the runtime expands a document it fills gaps with editor defaults (system font, centred, `#1E2A3A`), never with `theme` values.

**Do not set `template: true`.** The runtime deletes `collab` when minting from a template, then mints live-session keys with `on: true`, and the first save writes `ownerPriv` into the user's deck. Omitting `docId` already mints a fresh deck per open, so the flag only costs the sharing default.

**A missing `transition` defaults to `fade`,** so the key must be present on every slide and layout.

**charts-lite ignores most option keys silently.** `splitLine.show` and `axisLine.show` do nothing and the lines still draw; paint them in the ground colour instead.

**`measure()` returns the box width, not the text width,** and a trailing `<p>` adds its margin to the measured height.

## Reference

`node scripts/inflate_runtime.mjs runtime/Bento_Slides.bento.html --out .build/runtime` extracts the runtime as searchable minified JS. `rg` it to settle a question about app behaviour rather than guessing; that is how the collab and `template` behaviour above was confirmed.
